===== PAGINA 10 =====

 Qué pasa cuando hacés docker run
 1. La CLI arma un POST /containers/create y lo manda al socket
 2. El daemon resuelve la referencia de la imagen y hace pull si falta
 3. containerd desempaqueta los layers   → lowerdir; crea upperdir para este container
 4. El daemon crea el endpoint de red: netns, par veth, IP del IPAM, reglas de iptables
 5. Genera el config.json OCI: namespaces, mounts, cgroups, capabilities
 6. runc hace clone(), aplica cgroups, pivot_root, seccomp y exec()

 Los pasos 3 a 6 son exactamente los que hicimos a mano en la demo.

                                           docker run -d -p 8080:80 nginx

  # tabla nat, cadena DOCKER (simplificado)
  -A DOCKER ! -i docker0 -p tcp --dport 8080 -j DNAT --to-destination 172.17.0.2:80
  # y para el egress
  -A POSTROUTING -s 172.17.0.0/16 ! -o docker0 -j MASQUERADE

 Resumen
     El docker CLI es un cliente de la API del daemon; el socket es acceso root
     Cada flag de run se traduce en objetos del kernel: netns, cgroups, mounts, iptables
     Red: bridge propio como default sensato; publicar un puerto es DNAT, y el firewall del host no alcanza
     Volúmenes: la capa de escritura es efímera — volumen si el dato importa, bind si el path importa, tmpfs si
     no debe persistir
     Todo esto es lo que en la próxima clase se escribe declarativamente en Compose
