===== PAGINA 6 =====

 Terminación gradual del contenedor
 Secuencia de cierre iniciada por Kubernetes.

    Etapa                        Acción

    SIGTERM                      Se inicia la terminación.

    Drenar                       Dejar de aceptar trabajo nuevo.

    Finalizar                    Completar o cancelar en curso

    Cerrar                       Conexiones, ACK y flush.

    Salir                        Antes del plazo.


 Si se agota el grace period, el proceso recibe SIGKILL.
 Para HTTP: finalizar requests. Para workers: detener consumo y confirmar solo el trabajo completado.

===== PAGINA 7 =====

 Servidor HTTP en Go con cierre gradual
 Manejo de señales y drenaje de solicitudes.

  srv := &http.Server{Addr: ":8080", Handler: mux}
  stop, cancel := signal.NotifyContext(
    context.Background(), syscall.SIGTERM, syscall.SIGINT,
  )
  defer cancel()

  go func() {
    _ = srv.ListenAndServe()
  }()
  <-stop.Done()

  drainCtx, done := context.WithTimeout(
    context.Background(), 25*time.Second,
  )
  defer done()

  _ = srv.Shutdown(drainCtx)

 El tiempo de drenado debe ser coherente con terminationGracePeriodSeconds.

===== PAGINA 17 =====

 Configuración de probes en un Deployment
 Parámetros de startup, readiness y liveness.

  startupProbe:
    httpGet: {path: /health/startup, port: 8080}
    failureThreshold: 24
    periodSeconds: 5
  readinessProbe:
    httpGet: {path: /health/ready, port: 8080}
    periodSeconds: 5
  livenessProbe:
    httpGet: {path: /health/live, port: 8080}
    periodSeconds: 10


    Regla: el endpoint de liveness no debe fallar solo porque PostgreSQL o Redis estén caídos.

 Políticas de reintentos
 Criterios para reintentos seguros según el tipo de error.

    Situación                                           Decisión

    HTTP 503 transitorio                                Retry acotado en cliente si es seguro.

    Deadlock local irrecuperable                        Liveness + restart.

    Arranque incompleto                                 Startup / readiness.

    Config inválida                                     Fail fast + diagnóstico + alerta.

    Pago potencialmente duplicado                       Idempotencia antes del retry.
